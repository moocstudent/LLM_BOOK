## 低秩假设

LoRA 的全部数学在一行里:

```
W' = W + ΔW,  其中 ΔW = (α/r) · B · A
```

W 是冻结的原权重(d×d),A 是 r×d,B 是 d×r,而 r 远小于 d。训练时只有 A 和 B 更新。

**为什么这样可行?** 因为有一个经验观察:**微调造成的权重变化 ΔW 是低秩的。**

直觉上的解释是,微调要做的事情本身信息量很小。你在教模型「用这种格式回答」或者「按这种口径判断」——这是一个方向上的调整,不是重新学习语言。而一个 4096×4096 的矩阵有一千六百多万个自由度,远超表达这种调整所需。

秩 8 的 LoRA 用两个 4096×8 的矩阵表示它:6.5 万个参数,是原矩阵的 0.4%。

## 参数量:严格线性

参数量公式:

```
每个被适配的投影:2 · r · d
整个模型:      Σ(所有被适配的投影) × 层数
```

关键在于它对 r 是**线性**的,对原矩阵大小是**一次方**的(而原矩阵是二次的)。这就是压缩比能到几百倍的来源。

上面的实验里那张表让你看到具体数字:7B 模型、只适配 q 和 v、r=8,大约 400 万可训练参数(0.06%),适配器文件 8 MB。**8 MB 意味着你可以把它放进 git、通过邮件发给客户、在服务里几毫秒热加载。** 这个数字改变的东西比效果更多。

## α 与 r:必须一起调

α/r 是加在 ΔW 上的缩放系数。它的作用相当于给 LoRA 分支单独调了一个学习率倍数。

常见做法是 **α = r 或 α = 2r**,也就是缩放系数固定在 1 或 2。这样做的好处是:当你改 r 的时候,更新的量级不会跟着变——否则你改 r 的同时偷偷改了学习率,然后无法归因效果变化到底来自哪个。

这是一个真实的、常见的实验错误。请把它记成一条规则:**改 r 就同步改 α。**

初始化上还有一个细节:A 用随机初始化,B 用零初始化。这样训练开始时 ΔW = 0,模型完全等价于原模型——**微调从一个不破坏任何东西的起点出发。** 这个设计比它看起来重要。

## 该给哪些模块加

这是本章最有实践价值的一节,而结论可能和直觉相反:**模块覆盖面比秩更重要。**

具体来说,`r=8 全模块` 通常胜过 `r=64 只加 q/v`,而后者的可训练参数还更多。

原因回到第一章:注意力负责在位置之间搬信息,FFN 负责在位置上做变换,而**模型的「知识」和「怎么做」主要存在 FFN 里**。如果你的任务只是调语气和格式,q/v 够了;如果你要模型学会一种新的领域推理套路,不加 MLP 常常学不进去。

实践建议:

- **默认全上**(q, k, v, o, gate, up, down)。额外成本很小,而它免掉了「是不是模块选错了」这个排查方向。
- **秩从 16 开始。** 大多数任务在 8–32 之间饱和。
- **只在两种情况下用高秩(64+)**:数据量上万条,或者你在教一种真正新的能力而不是一种风格。

r 超过 64 在多数任务上是浪费:效果早就饱和,而你多付了显存和过拟合风险。你可以在实验里把 r 拉到 256,看「预估效果」几乎不动而参数量涨了 32 倍。

## LoRA 的局限

为了不给你一个过于乐观的印象,三条真实的局限:

1. **数据量很大时(十万条以上),全参微调的上限更高。** 低秩假设在「学一个新能力」的场景下会成为约束。
2. **叠加两个 LoRA 通常不奏效。** 两个适配器各自是在基座上训的,更新方向没有理由正交,直接相加常常互相干扰。要同时具备两种能力,重新用混合数据训一个。
3. **秩太低时会欠拟合。** r=1 或 2 在复杂任务上确实不够。

## 练习

1. 在实验里对比两个配置的可训练参数量和预估效果:`r=64, 只 q/v` 和 `r=8, 全模块`。哪个参数更多?哪个效果更好?用这个对比向别人解释为什么覆盖面比秩重要。
2. 手算一次:7B 模型(32 层、hidden 4096)全模块 r=16 的可训练参数量。然后和实验里的数字对一下。这个手算必须做一次,以后你看任何 LoRA 配置都能立刻估出规模。
3. 如果你手上有一个微调过的 LoRA,查它的 config 文件:r 是多少?α 是多少?target_modules 有哪些?按本章的建议,你会怎么改?
