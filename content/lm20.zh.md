## 把奖励解出来

DPO 的推导思路可以不带公式地讲清楚。

RLHF 的目标是「最大化奖励,同时不要离参考模型太远」。这个带 KL 约束的最大化问题有一个**闭式最优解**:

```
π*(y|x) ∝ π_ref(y|x) · exp( r(x,y) / β )
```

也就是说,最优策略完全由参考模型和奖励函数决定。而这个式子可以反过来解——把奖励用策略表示出来:

```
r(x,y) = β · log( π*(y|x) / π_ref(y|x) ) + const
```

**关键一步在这里:** 既然奖励可以用策略表示,那就把它代进奖励模型的那个成对比较损失里。代进去之后,奖励函数整个消失了,只剩下策略和参考模型:

```
L = -log σ( β · [ (log π(y⁺|x) - log π_ref(y⁺|x)) - (log π(y⁻|x) - log π_ref(y⁻|x)) ] )
```

这就是 DPO 损失。**没有奖励模型,没有采样,没有强化学习。** 它的形状和一个二分类损失几乎一样,训练过程和监督微调一样简单。

## 工程上的差别是决定性的

| | RLHF (PPO) | DPO |
|---|---|---|
| 需要训奖励模型 | 是 | 否 |
| 训练时需要在线采样 | 是 | 否 |
| 同时驻留显存的模型 | 4 个(策略、参考、奖励、价值) | 2 个(策略、参考) |
| 实现复杂度 | 高 | 低 |
| 超参敏感度 | 高(PPO 那一堆) | 低(基本只有 β) |
| 效果上限 | 略高 | 接近 |
| 对偏好数据质量的敏感度 | 中 | **高** |

前五行是 DPO 在实践中迅速普及的原因:它把一个需要专门团队维护的强化学习流水线,变成了一个可以在单张卡上跑完的训练脚本。

最后一行是它的代价,值得单独说。

## 为什么 DPO 更依赖数据质量

RLHF 里,奖励模型是一层缓冲:它在几万条比较上拟合出一个平滑的打分函数,单条错标的影响被平均掉了。

DPO 没有这一层。**每一对偏好数据都直接进入梯度。** 一对错标就是一次错误的梯度更新,而它不会被任何东西平滑。

具体后果:

- **偏好对必须有区分度。** 两个都很好的回答放在一起,没有信号可学,只有噪声。
- **长度偏见会被直接放大。** 如果你的标注员倾向于选更长的回答(这是人类标注里最顽固的偏见),模型会忠实地学到「长即好」,输出膨胀到基线的两倍。
- **偏好对数量要够。** 少于一两千对时,DPO 通常只带来噪声级别的提升。

对策也很直接:**标注时控制长度**(把长度相近的答案配对),**显式构造「同样正确但更短」的偏好对**,以及在评估时专门盯着平均输出长度这个指标。

## β 控制什么

β 在 DPO 里的角色和 RLHF 里的 KL 系数是同一个:它决定策略能离参考模型多远。

- **β 小(<0.05)**:约束松,模型可以大幅漂移。典型退化是学会「好答案的表面特征」——更长、更多小标题、更多免责声明——而不是更好的内容。
- **β 大(>0.3)**:模型被牢牢拴住,胜率提升有限。如果你观察到「DPO 之后几乎没变化」,先检查 β,再检查偏好对的区分度。
- **常用起点:0.1。**

上面的实验里那个「隐式奖励间隔」值得注意:它是被选中回答和被拒绝回答之间的对数概率差,也就是模型学到的偏好强度。它涨得太快通常不是好消息——那往往意味着模型找到了一个表面特征来区分两者。

## DPO 之后

DPO 之后出现了一批变体,值得知道名字和它们各自想解决的问题:

- **IPO**:改损失形式,缓解 DPO 在数据有噪声时的过拟合。
- **KTO**:不需要成对数据,只需要「这条好/这条不好」的单条标注——在数据收集上便宜很多。
- **ORPO**:把 SFT 和偏好优化合并成一个阶段,省掉参考模型。
- **SimPO**:去掉参考模型,用长度归一化的奖励。

它们的共同方向是**继续简化流水线并降低对数据的苛刻程度**。但在你的项目里,选哪个变体的影响通常远小于偏好数据本身的质量——这一点值得反复提醒。

## 练习

1. 在实验里把 β 从 0.01 扫到 0.6,记录胜率、漂移和退化风险三条曲线。找出你会选的那个 β,并说明理由。
2. 把长度偏见拉到 80%,看输出长度膨胀到多少。然后设计一个具体的标注流程来消除这个偏见。
3. 对着 DPO 的损失公式回答一个问题:如果一对偏好数据里两个回答完全一样,这个损失是多少?梯度是多少?这个思考能帮你理解为什么「区分度」是数据质量的第一要求。
