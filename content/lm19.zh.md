## 监督微调的天花板

SFT 的训练信号是「这条输入,标准答案是这个」。这个信号有一个结构性的局限:**它只能告诉模型什么是对的,不能告诉它两个都对的答案里哪个更好。**

而现实里「好」大量是相对的。同一个问题的两个回答都事实正确,但一个更简洁、一个更啰嗦;一个直接给结论、一个绕了三段;一个在不确定处明确说了不确定、一个含混过去。这些差别你无法通过写一个「标准答案」来教——因为标准答案只有一个,而你想传达的是一个偏好序。

偏好优化就是解决这件事的。

## 三段流水线

**第一段:SFT。** 用几万条人写的指令-回答对训练基座模型,让它先学会以助手的方式回应。这一步的产物有两个用途:后面的起点,以及 KL 惩罚里的**参考模型**。

**第二段:奖励模型。** 给同一个提示采样两个回答,让人标注哪个更好,用这些成对比较训一个打分模型。

为什么用成对比较而不是打绝对分?因为**人擅长比较,不擅长打分**。「这个答案 7.5 分」在不同标注员之间几乎无法对齐,而「A 比 B 好」的一致率高得多。奖励模型的损失函数就是让它给被选中的回答打更高的分:

```
L = -log σ( r(x, y⁺) - r(x, y⁻) )
```

**第三段:策略优化。** 让模型生成回答、奖励模型打分、按分数更新策略(通常用 PPO),同时用 KL 惩罚把策略拴在 SFT 模型附近:

```
目标 = E[ r(x, y) ] - β · KL( π || π_ref )
```

## 中间那一段是最脆弱的

这是本章最重要的一句话:**奖励模型是一个用几万条人类比较拟合出来的近似函数,而策略优化的本质就是去找它的最大值。**

任何近似函数在被极致优化时都会暴露它和真实意图之间的缝隙。具体表现:

- 模型发现奖励模型偏好长答案,于是回答越来越长。
- 发现它偏好礼貌和共情的措辞,于是每个回答都以「这是一个很好的问题」开头。
- 发现它偏好分点和小标题,于是连「今天几号」都要列三条。

**奖励分一路上涨,而人读起来越来越难受。** 这就是奖励黑客,我们在下一章会专门做一个实验室来看它。

KL 惩罚正是为此存在的:它给「离开参考模型」这件事定价,让策略不能为了刷分而漂到任意远的地方。所以那个 β 系数是一根缰绳——**太松会漂,太紧等于没训。** 上面的推演里你可以把它拉到两个极端亲眼看看。

## 关于奖励模型的准确率

一个容易误读的指标。你会看到奖励模型报告「在测试偏好对上 78% 准确」这类数字,而这个数字有一个天花板:**在困难的偏好对上,人类标注员之间的一致率通常也只有 75%–80%。**

所以当你的奖励模型准确率高于这个数,它很可能不是变得更懂好坏了,而是在**拟合标注偏见**——比如学会了「更长的通常被选中」这条捷径。上面的实验在准确率超过 82% 时会给你这个警告。

## 对齐税

RLHF 会让模型变得安全、礼貌、格式统一,同时也会让它变得单调、爱说套话、在创造性任务上明显变差。多样性下降是可测量的。

这不是 bug,是优化一个**单一**奖励信号的必然结果:任何被最大化的标量都会挤压掉它没有度量的维度。

缓解办法只有一个方向:**在偏好数据里显式加入你不想失去的那些维度的偏好**——比如构造「同样正确但更短」的偏好对来对抗长度膨胀,构造「表述新颖」的偏好对来保住多样性。这也是为什么偏好数据的构造比 RLHF 的算法细节更值得你花时间。

## 练习

1. 在推演里把 KL 系数拉到最小,记录「刷分行为」和「多样性」两个指标。然后拉到最大,再记一次。用这两组数字向别人解释 β 在拉住什么。
2. 手写一条奖励模型的损失函数,并解释为什么它只需要「哪个更好」而不需要「好多少」。
3. 为你自己的一个任务设计偏好数据的采集方案:提示从哪来、回答怎么采样(同一个模型不同温度?两个不同模型?)、标注员要回答什么问题、以及你要怎么控制长度偏见。
